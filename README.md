# SiteFilter 卡片过滤器（Chrome / Edge 扩展）

在指定网站的右下角放一个可拖动的悬浮球，点击展开面板，按
**女优 / 标签类别 / 片商 / 系列 / 导演 / 标题关键词 / 番号** 对列表卡片做
**屏蔽 · 收藏（金星描边）· 高亮（彩色描边 + 自动置顶）**。

> **屏蔽有两种档位**（面板/设置页一键切换）：
> - **硬屏蔽（默认）**：卡片从页面**完全移除**，列表自动重排，不留占位。
> - **软屏蔽**：卡片**灰化 + 模糊遮罩**、打上「已屏蔽」角标，中间浮出 **「仍然查看」** 按钮——
>   点一下即**临时放行该番号 24 小时**（并按番号生效，同一页其他被屏蔽的照旧）。
>   适合"大部分不想看，但偶尔想确认一下有没有误杀"的场景。

另外附带两个独立能力：
- **番号收藏夹**：卡片 hover 点 ♥ 即可把整部片子存进收藏夹（带标题+链接），可"只看★番号"。
- **下载链接探测**：任意网页自动探测磁力 / 电驴 / 迅雷 / 种子 / 网盘链接，页面内加标记，面板里一键复制。

规则写多了之后的配套能力（v1.1.0 新增）：
- **规则体检**：把 0 命中的规则逐条说明原因，预警命中面过宽的屏蔽词，默认不勾选待删项。
- **规则调试器**：卡片右键看这张卡的**逐条规则判定过程**，用的是页面里同一份逻辑。
- **候选规则**：后台按「覆盖率 × 精确率」归纳建议，一键采纳 / 忽略。
- **临时规则**：右键「临时屏蔽 1 / 7 / 30 天」，到期后台自动移除。
- **场景档位 / 月度回顾 / 已看自动记录**。
- **加密备份**：口令保护（PBKDF2 25 万次 + AES-GCM 256），适合放网盘。

> 数据 100% 存在本机（`chrome.storage.local`），**没有任何服务器、没有任何上传**。
> 默认不做任何自动网络请求（加密用的是浏览器内置 WebCrypto，不是调远端接口）。
>
> ⚠️ **唯一的例外**：设置页「番号站数量补足」是**默认关闭**的。它开启后，扩展会在
> JavDB580 上额外抓取列表页来填补被屏蔽卡片的空位（不带 Cookie、限速、最多 3 页）。
> 除这个开关主动打开的情况外，扩展不会发起任何网络请求。

> 🔌 **部分功能需配合 [Universal Web Collector](https://github.com/LeonZhangDev/universal-web-collector) 使用。**
> 屏蔽 / 规则 / 收藏 / 推荐 / 下载链接探测 / 备份等**全部核心功能开箱即用、零额外依赖**；
> 只有「XChina 交给 Collector 下载」这一类需要配套项目 + 本机桥接。
> 详见 [一·五、依赖说明](#一五依赖说明哪些功能需要-universal-web-collector)。

## 一、安装（开发者模式加载）

1. 把整个 `site-filter` 文件夹放在一个**不会被删除的固定位置**（不要放在"下载"里）。
2. Chrome / Edge 打开 `chrome://extensions`（Edge 是 `edge://extensions`）。
3. 打开右上角 **「开发者模式」**。
4. 点 **「加载已解压的扩展程序」** → 选择 `site-filter` 文件夹。
5. 工具栏出现图标即成功。建议点「图钉」把图标固定到工具栏。

> 加载时会提示"读取和更改您在所有网站上的数据"，这是因为内容脚本声明在全部网址上注入，
> 以便你后续随时新增监管站点、以及**在任意网页做下载链接探测**。
> 在列表外的站点上，脚本只做链接探测，不做任何卡片处理。

### XChina 相册/视频交给 Universal Web Collector

XChina 照片和视频详情页会显示 **交给 Collector 下载**。扩展只负责预览、建立任务关联和显示摘要；网页解析、登录状态、下载、重试与输出目录都由 Universal Web Collector 管理。

1. 在 Universal Web Collector 项目目录中运行 `integrations\sitefilter-native-host\install-native-host.ps1`，按向导选择 Collector 项目和 WSL 发行版。
2. 重新加载 SiteFilter，回到 XChina 详情页，点击“重新检测”。扩展不会自动打开 Collector 管理页。
3. 预览确认后创建任务。如果已有完成任务，需要再次明确确认才会增量重新下载；失败或暂停任务会引导到原任务重试/恢复。

再次访问同一内容时，页面会恢复最新关联任务。若 Collector 提示需要登录，只有点击“启动登录”才会打开 Collector 的 WSLg 登录会话。SiteFilter **不会读取、导出或传输 Chrome/Edge Cookie**。

任务终态通知采用“最多一次”策略：扩展会先在本地标记通知已领取，再请求浏览器显示固定 ID 的通知。如浏览器明确返回创建失败，当前服务工作者会回滚标记以便重试；若服务工作者恰好在两步之间终止，可能漏掉一次通知，但不会因重启反复弹出。

## 一·五、依赖说明：哪些功能需要 Universal Web Collector

SiteFilter 是**纯前端扩展**（Chrome / Edge MV3，无构建步骤、无服务端进程）。
**绝大部分功能开箱即用，不需要任何配套项目**：

| 功能 | 需要 Collector？ | 说明 |
|---|---|---|
| 卡片屏蔽（隐藏 / 保留占位 / 模糊三档） | ❌ 不需要 | 全靠页面内 CSS class，纯本地 |
| 规则管理 / 规则体检 / 调试器 / 候选规则 | ❌ 不需要 | 只读 `chrome.storage.local` |
| 番号收藏夹 / 待看队列 / 发现库 / 推荐 | ❌ 不需要 | 纯本地计算 |
| 下载链接探测（磁力 / 电驴 / 迅雷 / 种子 / 网盘） | ❌ 不需要 | 只解析当前页面 DOM |
| 导出 HTML 片单 / 加密备份 | ❌ 不需要 | 浏览器内置 WebCrypto |
| **XChina 相册/视频「交给 Collector 下载」** | ✅ **必需** | 详情页控制条；缺桥接时提示「未安装本机桥接」 |
| **网页解析 / 登录态 / 下载 / 重试 / 落盘** | ✅ **必需** | 这些**全部由 Collector 负责**，扩展不做 |
| **任务状态回显与终态通知** | ✅ **必需** | 无 Collector 则无任务可关联、无通知 |

也就是：**扩展是「眼睛和手」，Collector 是「干活的」**。扩展只做页面控制、预览确认、
任务关联与状态回显；真正的抓取、下载、去重、输出目录全部属于 Collector。

接线三步（细节见上一节）：

1. 部署 **Universal Web Collector** 本体（仓库：
   `https://github.com/LeonZhangDev/universal-web-collector`）；
2. 在 Collector 项目目录下运行
   `integrations\sitefilter-native-host\install-native-host.ps1`，
   注册 **Native Messaging 本机桥接**（按扩展固定 ID
   `jaihdgjnnpmiabeoefmihmjhoodcjlhf` 注册，Chrome / Edge 各一份）；
3. 回到扩展，在 XChina 详情页点「重新检测」。

> 扩展**不会**直接请求 `localhost`，也**不会**读取 / 导出 / 传输浏览器 Cookie。
> 所有 Collector 通信都经 Native Messaging 桥接校验后转发。
> 因此若只关心屏蔽与收集类功能，**可以完全不装 Collector**，扩展照常工作。

> 裸域 `https://xsijishe.net/` 也能匹配（扩展对 `*://*.域名/*` 额外兜底了裸域）。

> **跨站内容 ID（cid，v1.2.0 起）**：♥ 番号收藏 / ⏳ 待看 / 已看 / 软屏蔽「仍然查看」都按 **cid** 记录。
> 番号站的 cid 就是番号本身（老数据不用迁移）；非番号站没番号，就从链接抽站点自己的 ID 并加前缀 ——
> PornHub → `ph:<viewkey>`、YouPorn → `yp:<作品号>`、西斯寂舍 → `dz:<帖子号>`。
> 所以这些站上 ♥ 和 ⏳ 也能用了（以前因为抽不出番号，按钮压根不渲染）。抽不出 ID 就留空，不拿垃圾当主键。

> **JavDB 的三个域名算同一个来源（v1.2.0 起）**：`javdb.com` / `javdb571.com` / `javdb580.com`
> 归一到来源组 `javdb`。发现库按来源组记账，同一个人不会因为你在三个镜像上各逛一次就被记成三个来源。

新增站点两种方式：

- **工具栏图标 → 弹窗** →「把当前站点加入监管列表」（自动按当前域名生成通配规则）。
- **完整设置 → 监管站点** → 手填匹配规则，例如 `*://*.example.com/*`。

## 三、悬浮面板怎么用

右下角小球：

- **单击**：展开 / 收起面板
- **拖动**：挪到任意位置（位置会记住）
- **锁定位置**（v1.2.0）：面板标题栏的 🔓/🔒 按钮，或 **Alt + L**，或设置页开关「锁定悬浮球位置」。
  锁定后拖不动但**仍能点击开合**，球右下角会挂一枚小锁 —— 摆好位置后锁上，就不会被误挪走。
- **Alt + F**：开合面板 · **Alt + S**：SFW 模糊 · **Alt + B**：老板键 · **Alt + L**：锁定球 · **Esc**：关闭
- 窗口缩小时球会自动收回可视区（v1.2.0 起），不会半个球飘到屏幕外。

### ⌨️ 卡片键盘导航（面板打开时，可全程不碰鼠标）

| 键 | 作用 |
| --- | --- |
| `J` / `K` | 在页面卡片间向下 / 向上移动当前项（青色描边标记） |
| `B` / `F` / `H` | 对当前卡片直接 **屏蔽 / ★收藏 / 高亮** |
| `P` | 把当前卡片加入 **⏳ 待看队列** |
| `Enter` | 打开当前卡片的详情页 |

> 上面是**默认键位**。所有键位都可以在设置页「快捷键」卡片里改成你顺手的（见
> [快捷键可自定义](#快捷键可自定义v101-新增)）。

### 🖱 卡片右键菜单

在任意卡片上右键，弹出菜单：**按女优屏蔽 / 收藏 / 高亮**（列出该卡全部女优，逐位可点）、
**临时屏蔽 1 / 7 / 30 天**（v1.1.0 新增）、**调试这张卡**（v1.1.0 新增）、**加入 ⏳ 待看**、
**复制番号 / 复制标题**、以及 **多站搜索**（javbus / javdb / javdb580 / xchina 一键直达）。
纯本地拼 URL，零网络请求。点空白处关闭。

- **临时屏蔽**：点一下即以该卡的女优建一条**带有效期**的屏蔽规则（1 / 7 / 30 天），
  到期后后台自动移除该规则 —— 适合"这个人的片子最近不想看，过阵子再说"。
- **调试这张卡**：浮出调试面板，列出该卡片的字段摘录、结论（哪条规则生效）、以及
  **逐条规则的判定步骤**（每步通过 / 不通过 + 原因）。详见下文「规则调试器」。

**番号多站直达**：面板的 ★番号 / ⏳待看 列表里，每个番号下方也会带一排「多站直达」按钮，
省掉"复制番号 → 开另一个站 → 粘贴"的来回跳。

面板的 13 个页签：

| 页签 | 内容 |
| --- | --- |

| 女优 / 标签 / 片商 / 系列 / 导演 | 自动识别本页出现的所有该维度条目，右侧三个按钮：**屏蔽 · ★收藏 · 高亮** |

| 📅 今日 | **每日自动推荐**：一批女优/片商/系列（含头像 + 质量分进度条 + 推荐理由 + 「去看 / 我看过了」） |
| 🔗 相似 | **相似女优推荐**：以你收藏/高亮的女优为种子，按共同标签/片商/系列的 **IDF 加权相似度**推荐；带**相似度进度条**，点「为什么？」可下钻看**相似度构成 / 共同点明细 / 共同出演作品** |

| ⏳ 待看 | **待看看板**：按 **高 / 中 / 低** 优先级分栏；每张卡可切换优先级、**点一下写备注**；可标记已看、导出 Markdown 片单 |
| ★ 番号 | 番号收藏夹；顶部可按 **全部 / 已看 / 未看** 筛选；可复制全部、移除、清空 |

| 本页 | 当前站点、匹配规则、卡片选择器、生效规则数、各维度识别数量；含 **🎯 点选卡片** 按钮 |

顶部按钮含 **↶ 撤销**（回退最近 40 次规则改动）、**📥 导入本页收藏**（仅监管站点显示）。

顶部开关：**过滤 / SFW / 只看收藏 / 只看★番号 / 软屏蔽 / 规则预览 / 老板键**。
**规则预览**：打开后命中屏蔽规则的卡片**不真正隐藏**，只打上红色虚线描边 + 「预览：将屏蔽」角标，
配合统计条的「（预览 N）」就能先看清会误杀哪些卡片，确认无误后再关掉预览正式生效。

> 打开 **软屏蔽** 后，命中屏蔽规则的卡片不再消失，而是**灰化 + 模糊**并浮出 **「仍然查看」** 按钮；
> 点它即临时放行该番号 **24 小时**（按番号生效）。关掉开关立刻回到"完全隐藏"。

**评分 / 日期 快速筛选**（面板内「筛选」栏）：按 **评分下限**（≥3.0 / ≥4.0 / ≥4.5）和 **发行日期下限** 实时隐藏不匹配的卡片。
> 提取是"尽力而为"的：依赖站点把评分写在 `class` 含 `rate/score/star` 的元素、把日期写在 `class` 含 `date/time` 的元素（或卡片文本里的 `2024-05-12`）。站点结构各异，提取不到时筛选自动放行全部，不影响使用。

**悬停查原因**：鼠标移到任意被处理的卡片上（**包括被屏蔽的**），会浮出一个小面板，逐条告诉你「命中了哪条规则、什么动作、作用范围、命中值」。排查误伤不用再猜。
可在「通用设置 → 开关」里关掉（`悬停显示「为什么被处理」浮层`）。

**冲突提示**：某个女优/标签同时被「屏蔽」和「收藏/高亮」时，面板顶部弹橙色警告条并点名，设置页规则列表上方也有同样的警告 + **一键修复**按钮（保留屏蔽、移除冲突的收藏/高亮）。

**↶ 撤销**：每一次规则改动（新增、删除、切换动作、批量、全屏蔽、清空）都会在改动前存一份快照，最多回溯 40 步。点错了一键回退，不用手动删。

**状态记忆**：已经在规则里的名字，对应按钮会高亮显示；再点一次即移除。


### 傻瓜化：发现库 + 🆕推荐 + 每日新人（不用打字）

核心思路：**规则从你浏览过的页面里"点"出来，而不是手动输入。**

- **发现库（后台自动积累）**：你正常浏览监管站点时，扩展默默记下见过的每个女优 / 标签 / 片商 / 系列 / 导演（只记名字 + 出现次数 + 首次出现时间，**不记录任何观看行为**）。被屏蔽规则命中的内容不会被记录。
- **🆕推荐 页签（可视化卡片墙）**：列出"见过但还没建规则"的内容，每张是一张卡片，显示类型 / 出现次数 / NEW 角标。
  - **点一下卡片**就循环切换：`无 → 屏蔽 → 收藏 → 高亮`，再点回到无。所见即所得，不用选类型、不用打字。
  - **批量选择**按钮：进入勾选模式，框选多个后一键"全选屏蔽 / 全选收藏 / 全选高亮"。
- **每日新人自动推荐**：推荐标签上带**红色数字徽标**=近 7 天新面孔数量；当天第一次打开面板且确实有新人时，面板会**自动跳到 🆕推荐**页。今日新发现 / 7 天新面孔 / 待标记总数都写在推荐页顶部。
- **首次引导**：第一次打开面板会显示一条引导提示，告诉你 ♥ 收藏按钮和 🆕推荐 页在哪，点"知道了"即不再显示。

### 📅 今日推荐（每日自动、含头像、按质量排序、去重）

面板里的 **📅 今日** 页是一套**独立于 🆕推荐**的、由后台**每天自动生成一次**的推荐流，目标是"每天给你一批值得关注的新/优质内容"。

**生成机制（后台 `alarms`，每天触发一次）**
1. 从发现库里挑出候选（**维度可配**：女优 / 片商 / 系列，默认只推女优），自动排除：①已被任何规则（屏蔽/收藏/高亮）覆盖的人；②近 N 天已经推荐过的人（`recHistory` 去重，默认窗口 14 天）；③**已看过番号较多**的人（见下）；④在每日推荐里被你**手动屏蔽过**的人（反馈闭环）。
2. 把候选分成两组：
   - **新面孔**：首次出现在 **30 天内**的人（无论质量，优先展示）。
   - **旧的高质量用户**：首次出现超 30 天、且**质量分 ≥ 设定阈值**的人。
3. 两者按"新面孔优先、组内按质量分降序"拼成当天的一批（上限可设，默认 12，其中新面孔上限 6）。

**排除"已看过的作品"（默认开，可在设置关闭）——粒度已细化到「她的具体片子」**
- 点开过的番号会自动记进"已看"（键是番号）。同时扩展在浏览时被动记下**每位女优出现在哪些番号**（`cooc[name].w`）。
- 两者**求交**：算出"她已知的作品里，你已看过多少部"，**比例 ≥ 阈值（默认 75%）** 时就不再作为"待发现"推荐。
  - 例：她出现过 4 部、你点开过 1 部 → 25%，照常推荐；你点开过 4 部 → 100%，不再推荐。
  - 推荐理由会写明 **「你已看 1/4 部」**，一眼看出为什么推她。
- 数据不足（已知作品 **< 3 部**）时自动退回旧的整体判断：**累计已看 ≥ 3 且占总出现次数 ≥ 50%** 才排除。
- 阈值可在 **设置 → 通用设置 → 每日推荐 → 「已看该人作品 ≥ N% 才排除」** 调整（50%~100%）。
- 这样 📅今日 始终给你**还没怎么看过的**女优。想连熟脸也推，关掉「排除已看过多的人」即可。

**推荐下钻 & "我看过了"（体验闭环）**
- 每张卡有 **「去看」** 按钮 → 直接跳到该女优/片商/系列在对应站点的主页（链接来自发现库，无额外请求）。
- **「我看过了」** 按钮 → 立刻把该条目从今日流移除，并记进"已看"+推荐反馈，下次不再推。

**"质量"怎么算（建议的几项指标，已落地，且可调）**
质量分 0~100，由四项加权（可在设置页用滑块调，或勾选"用采纳率自动调权重"）：
| 指标 | 默认权重 | 说明 |
| --- | --- | --- |
| 影片评分 | 40% | 取发现库里记录的评分（假设 0~10，归一化） |
| 作品数量 | 25% | 作品越多越"资深"，用对数压缩避免被巨量作品绑架 |
| 人气（被你见过的次数） | 20% | 出现越多说明曝光越高 |
| 近期活跃度 | 15% | 最近被访问的越近权重越高（90 天衰减） |

> 哪些算"质量比较高"——我的建议就落在上面四项：**评分高、作品多、你常刷到（人气）、近期仍活跃**。
> 评分/作品数据来自你浏览时被动采集的 star 页（头像、链接一并记下）；如果某站没采集到，则该人只能靠"人气+活跃度"计算，分数偏低，此时可在 📅今日 页点 **「补全头像资料」**（需你当前已打开对应站点页，否则会被跨域拦截）。

**质量分可视化**
- 每张卡上的「质量 N」用**进度条**展示（紫→青渐变，长度 = 质量分占比），一眼看出高低，不用看数字。

**图片（头像/展示图）**
- 推荐卡片是**图片墙**：有头像的显示真实头像，没有的显示**姓名首字占位**（不会空着）。
- 头像在浏览含女优的列表/详情页时**被动采集**（不额外发请求）。

**操作**
- 每张卡右侧：**屏蔽 · ★收藏 · 高亮 · 去看 · 我看过了**，点一下即生效。
- 顶部：**重新生成**（强制刷新当天推荐）、**补全头像资料**（从 star 页拉取头像/评分/作品数）、**全部收藏**（一键把今天这批全加进收藏）。

**每日推荐通知**
- 生成完成后弹一条浏览器通知"今日推荐已就绪"，点开进设置页。**可在设置关闭**。

**可调（完整设置 → 每日推荐）**
- 开关、生成后弹通知、**排除已看过多的人 + 排除阈值（已看该人作品 ≥ N%）**、每日上限、新面孔上限、旧用户入选最低质量分、不重复窗口天数、**推荐维度（女优/片商/系列多选）**、**质量分权重滑块**、**用采纳率自动调权重**。
- **立即生成今日推荐**按钮；**清空推荐历史**（不影响已建规则）。

**跨设备云同步**
- 完整设置里有「云同步」开关：开启后数据走 Chrome/Edge 账号同步（**不经任何服务器**，由浏览器厂商同步通道负责），换电脑自动带上规则 / 发现库 / 每日推荐。首次开启请点「立即同步到云端」把本机数据推上去。本地数据始终保留一份镜像。
- 推荐反馈（`recFeedback`）、推荐历史（`recHistory`）、每日推荐（`dailyRecs`）均随同步搬运。

> 仍不联网：推荐完全来自本地发现库，不自动访问任何网站。头像补全是**你手动点按钮**时才发生、且只在你已打开对应站点页的前提下。

### 🔗 相似女优推荐：为什么用「IDF 加权 + 多信号余弦」

面板里 **🔗 相似** 页。思路不是"看谁跟谁同框出现得多"，而是**把每个女优表示成一个特征向量，算向量夹角**。
朴素做法（数共同出现的次数）有个致命问题：**"高清""中文字幕"这种满大街的标签会让所有人都跟所有人像**。所以做了几层修正：

**1）特征维度与权重**（每个维度不同重要度）

| 维度 | 权重 | 理由 |
| --- | --- | --- |
| 标签 / 类别 | 1.0 | 最能反映口味（题材偏好） |
| 系列 | 0.9 | 系列通常代表固定风格 |
| 片商 | 0.8 | 有区分度但比题材粗 |
| 导演 | 0.6 | 命中率低，权重压低避免噪声 |

**2）IDF 加权 —— 这是最关键的一步**
对每个特征计算 `IDF = log(1 + N / df)`（N = 有共现数据的人数，df = 用过该特征的人数）。
**罕见特征权重高、大众特征权重低**。举例（真实测试数据）：种子同时有「稀有一」和「大路货」两个共同标签，罕见那个给出的相似度是 **60%**，大众那个只有 **25%** —— 差 2.4 倍。

**3）频次对数压缩**：同一特征共现 10 次不等于比 1 次像 10 倍，用 `log(1 + 次数)` 抑制头部。

**4）余弦归一化**：除以两人各自的特征模长。否则"作品巨多的女优"会因为特征多而跟谁都像。

**5）种子聚合**：以你 **收藏（权重 1.0）/ 高亮（0.7）** 的女优为种子，
候选得分 = `0.6 × 最像的那位种子 + 0.4 × 与所有种子的加权平均相似度`。
既保留"和某一位极像"，又兼顾"整体品味一致"。

**6）排他**：已被任何规则（屏蔽/收藏/高亮）覆盖的人、以及你在每日推荐里**手动屏蔽过**的人，直接不推。

**推荐理由**会写明"因为你收藏了 X · 共同点：A、B、C · 共同出演 N 部"，直接告诉你为什么。

**7）相似度进度条 + 「为什么？」下钻（点开看依据）**

每张相似卡上：

- **相似度进度条**：紫→青渐变条，长度 = 相似度占比，一眼比高低（旁边同时保留 `相似 62%` 徽章）。
- **「为什么？展开详情 ▼」**，点开后给出四块证据：

| 区块 | 内容 |
| --- | --- |
| **相似度构成** | 标签 / 系列 / 片商 / 导演 四个维度各贡献了多少百分点（横条） |
| **共同点明细** | 每个共同特征：维度 + 名称 + **稀有度(IDF)** + `种子N次/她N次`，按对相似度的贡献降序 |
| **共同出演作品** | 两人出现在**同一部作品**（同一张卡片）里的番号，可点击直达 |
| **她的其他作品** | 这个人你在页面上见过的其他番号 |

> 「共同出演」是真实交集：扩展在浏览时顺带记下"哪个女优出现在哪个番号"（每人最多留 40 部，纯本地）。
> 所以当一部片里有两位女优同时出现，就能被你一眼看到"她俩是搭档过"。

> **成本与隐私**：共现数据是你浏览时本地被动累积的（女优 ↔ 标签/片商/系列/导演，以及女优 ↔ 番号），只在本地算，零网络请求。
> 数据不够时相似页会提示你先多浏览几页、或先收藏几位女优再点「重新计算」。

## 五、下载链接探测（跨站点）

在**任意网页**（不限于监管列表）都会自动运行，探测到的链接会在页面上打上绿色虚线标记，
并在面板「下载」页集中列出。

**支持的类型**
- `magnet:` 磁力链接
- `ed2k:` 电驴、`thunder:` 迅雷
- `.torrent` 种子文件直链
- 网盘直链：**百度网盘 / PikPak / 115 / 夸克 / 阿里盘 / 天翼云 / Google Drive / MEGA / MediaFire / OneDrive / Dropbox / send.cm / SolidFiles**

**三条扫描来源**（这是关键，很多站把磁力藏在属性里）
1. `<a href="...">`
2. `data-clipboard-text`、`data-url`、`data-link`、`data-magnet`、`data-copy` 属性
3. 页面正文里的裸 `magnet:` / `ed2k:` / `thunder:` 文本

**磁力链接的深度解析**（不只是抓串）
- **完整 `xt` 解析**：同时认 `urn:btih:`（BT v1，40 位 hex / 32 位 base32）与 `urn:btmh:`（BT v2，multihash）。
  参数顺序无关 —— `dn=` / `tr=` 排在 `xt=` 前面的写法同样能认（部分站的「复制磁力」按钮就是这种顺序）。
- **体积取权威值**：优先读链接自带的 `xl=`（精确字节数），其次 `size=` / `length=` / `fsize=`，
  都没有才从文件名里猜（只认「数字+单位」的独立词，不会把番号里的数字当体积）。
- **同种子归并**：`infohash` 相同的多条磁力合并成一条，文件名取更完整的那个，
  `tr=` 取并集 —— 列表里不会再出现同一部片换 tracker 就重复两行的情况。
- **按信息完整度排序**：磁力优先于其它类型；同类型内「有体积+有画质 > 有体积 > 有画质 > 其余」。
- 列表里展示 BT hash 前 10 位、文件名、体积、画质、tracker 条数（v2 种子带 `V2` 标记）。

**顺带提取**：文件大小（GB/MB）、清晰度（4K/1080p/720p…）、网盘来源，直接显示在列表里。

> 残缺的 `magnet:` 串（没有 `xt=`，例如只剩一个 `dn=`）会被丢弃，不会当成链接展示。

**操作**：每条右侧「复制」；顶部「复制全部磁力」「复制全部链接」。归并后复制出去的是信息最全的那一条（含全部 tracker）。

可在「完整设置 → 通用设置」里分别关闭：探测本身 / 页面内标记 / 非监管站点也探测。

### 规则体检（v1.1.0 新增）

规则库攒到几十条以后，最烦的两种情况：**看着在生效其实一直没命中**、和**一条规则把太多东西挡掉了**。
「规则管理」页底部的**规则体检**卡片就是干这个的。

**① 零命中预警**——对「启用中、创建超过 7 天、`hits` 仍为 0」的规则，逐条给出**可能的原因**：

| 原因 | 说明 |
| --- | --- |
| 规则当前是关闭状态 | 勾选框没勾 |
| 所属分组当前关闭 | 分组页把整组关了 |
| 临时规则已到期 | 带有效期的规则到期后失效 |
| 限定只在某些站生效 | 你可能没在那些站刷到过 |
| 匹配方式是「精确」 | 页面文本多一个空格就不算命中 —— 多数情况应改成「包含」 |
| 用了正则 | 建议先到「正则测试器」里确认写法能命中 |
| 作用范围限定过窄 | 该维度没被识别出来就永远命中不了 |
| 条件表达式为假 | 表达式不成立时整条规则不参与 |
| 评分 / 日期条件 | 卡片没解析出评分或日期就不命中 |

**② 命中过宽预警**——对**屏蔽**规则，用发现库估算影响面：同类条目里超过 **70%** 都带这个词就提请，
并列出命中的例子帮你判断。典型误伤词是「高清」「中文字幕」这种，建议改成**标题词**或**限定作用范围**。

**③ 安全操作**——待删列表**默认一条都不勾**，需自行勾选后再点「删除勾选的规则」或
「勾选的规则全部关闭」；每条旁边有「改到规则库」直接跳到该行并高亮。

> 与「数据看板 → 死规则清理」的区别：那个只按 0 命中一刀切删除；规则体检**给原因、给建议**，
> 多数情况改一下就能生效，不必删。

### 候选规则（自动学习，v1.1.0 新增）

后台每天归纳一次：**你屏蔽的人身上有哪些共同标签 / 片商 / 系列**？「发现 & 推荐」页底部的
**候选规则**卡片列出建议，每条可一键**采纳**或**忽略**。

判定用**两个指标同时达标**，这是这个功能能不能用的关键：

| 指标 | 含义 |
| --- | --- |
| **覆盖率** | 你屏蔽的人里，有多少带这个特征（≥ 50%） |
| **精确率** | 带这个特征的人里，有多少被你屏蔽（≥ 60%） |

只看覆盖率会推出「高清」这种人人都有的无意义词 —— 覆盖率 100% 但精确率可能只有 5%。
两个都够高，才说明这个特征**确实是你讨厌的那类**。

其他细节：
- 已被现有规则覆盖的特征**不会重复推**（有「丝袜」规则了就不会再建议「丝袜」）。
- 「忽略」会写进 `dismissedLearn`，以后不再提；可随时「清空已忽略名单」。
- 采纳建出的规则带 `learnedFrom` 溯源信息（当时的覆盖率 / 精确率），方便日后回看是怎么来的。
- 归纳不出稳定共性时（种子少于 3 条、或样本少于 6 个条目）不给建议，避免瞎推。

### 场景档位（v1.1.0 新增）

「分组」页底部的**场景档位**：把当前这套「每条规则的启用状态 + 每个分组的开关 + 几个关键行为开关」
（SFW / 只看收藏 / 首条命中 / 软屏蔽 / 规则预览）存成一个档位，之后一键来回切。

典型用法：存一个「日常」（该开的开、该关的关）和一个「扫片模式」（临时屏蔽组打开）来回切。

> **边界**：档位保存的是**开关状态**，不含规则内容本身。所以你新增 / 删除规则后，
> 旧档位对**新规则不做处理（保持现状）**，不会把规则删掉。这是有意的设计 ——
> 档位切换不该有"看不见的删除"。

### 月度回顾（v1.1.0 新增）

> 逐月增量没有单独记录，用"最近命中时间落在本月"来近似。

### 临期规则：到期自动失效（v1.1.0 新增）

想临时挡一阵子、之后自动恢复的场景：

- **卡片右键** → 快捷菜单里有「**临时屏蔽 1 天 / 7 天 / 30 天**」。点一下即以当前卡片的女优建一条带有效期的屏蔽规则。
- **规则编辑行**里有「**有效期至**」日期输入框，可设具体到期日；或点「**设为永久**」清掉有效期。
- 规则表新增「**有效期**」列：永久规则显示「永久」，临时规则显示剩余（如「3 天」），
  已到期的显示「已过期」（红色）。

设计要点：**到期后后台会真正移除该规则**，而不是"仍生效但每次判定时跳过"——
免得规则库只增不减。移除的会记进 `expiredLog`（上限 200 条）供回查。

### 已看自动记录（v1.1.0 新增）

打开**详情页**时自动把该番号记为「已看」，不用再手动点。

### 规则调试器（v1.1.0 新增）

**卡片右键 → 「调试这张卡（看规则判定过程）」**，右上角浮出面板，内容包括：

- **卡片字段摘录**：标题 / 女优 / 标签 / 片商 / 系列 / 评分 / 日期（即引擎实际看到的内容）。
- **结论**：这张卡最终被怎么处理、来自哪条规则。
- **逐条规则的判定过程**：每条规则展开成若干步骤 chip，每步显示「通过 / 不通过」及原因
  （如 `日期≥：不通过（2021-03-04）`、`作用范围：通过`）。
- **状态标注**：`已关闭` / `已过期` / `分组关闭` / `★ 生效` / `命中但被压过`。
- 带有效期的规则显示「有效期至 …」。

> **为什么这个面板可信**：它调用的 `matchRuleDetail` 和 `decideCard` 就是页面过滤时用的**同一份实现**，
> 只是多传了一个 `steps` 数组来记录过程。**面板说什么，页面就做什么** —— 不是另写一份近似推断
> （那种实现最容易跟真实行为走偏，调试器反而误导人）。

### 规则条件：评分 / 发行日期（第 8 项建议）

编辑规则时除「匹配方式」外，还可加三个**可选条件**（留空即不启用）：

| 条件 | 含义 | 典型用法 |
| --- | --- | --- |
| **评分 ≥** | 卡片评分达到该值才命中 | `评分 ≥ 4` + 动作「高亮」→ 好片自动置顶 |
| **发行日期 ≥** | 不早于该日期才命中 | `2024-01-01` → 2024 年后的新片才高亮 |
| **发行日期 ≤** | 不晚于该日期才命中 | 配合上面做区间筛选 |

即"**2023 年后 + 评分 ≥4 → 自动高亮**"这种规则是直接可写的，不再只是面板里的临时筛选。

### 规则条件：布尔表达式（v1.0.1 新增）

上面那三个条件是"顺带加一点限制"。想要**真正的组合条件**时，新建/编辑规则里多了一个
**「条件表达式」**输入框，语法如下：

```
字段 运算符 值              ← 一个原子条件
&&  ||  !  ( )              ← 与、或、非、括号，任意嵌套
```

| | |
| --- | --- |
| **字段** | `title` `actress` `tag` `maker` `series` `director` `code` `all` `rating` `date` |
| **文本运算符** | `~` 包含 · `=~` 正则 · `!~` 正则不匹配 · `=` / `==` 等于 · `!=` 不等于 |
| **数值运算符** | `>` `>=` `<` `<=` —— 只能用于 `rating` / `date` |

例子：

```
rating >= 4 && date >= 2023-01-01
title =~ /^(SSIS|STARS)-\d+/ && !(tag ~ 巨乳)
(code =~ /^ABC-/ || maker ~ S1) && rating >= 4.5
丝袜 || 高跟                      ← 省略字段时等价于 all ~ 值
```

设计上的几个关键点：

- **设置页里的「表达式测试器」和页面跑的是同一份代码**（独立文件 `expr.js`，由 manifest 在
  `content.js` 之前加载、设置页也用 `<script src="expr.js">` 引入）。所以"测试器通过"就等于
  "页面上会命中"——不存在两份实现慢慢走偏、测试器骗人的情况。
- **坏表达式不会炸页面**：语法错误既不会命中任何卡片，也会写进本地**错误日志**（设置页可查）。
  测试器里会直接标出错误位置。
- **缺数据的卡片按"不命中"处理**：没评分 / 没日期的卡片参与 `>` `>=` `<` `<=` 一律不命中，
  与简单模式的行为一致，避免"没有评分 = 评分 0"这种误伤。
- **日期可以只写一半**：`date >= 2023`、`date <= 2024-06` 都符合直觉（作上限时缺位补满
  12/31，作下限时补 0）。
- 表达式规则在规则库里带一个 **「表达式」** 徽标；点 ✎ 仍可继续微调动作 / 站点 / 颜色。
- 测试器里还有一个 **「模拟卡片」** 文本框（每行 `字段: 值`），改几个字段就能当场验证
  表达式命中不命中，不用真去网站上试。

### 加密备份（v1.1.0 新增）

备份文件可能包含你看过 / 屏蔽过的全部记录 —— 放进网盘不合适。备份卡片里多了
「**导出加密备份**」：给一个口令，文件被加密后再下载。导入时自动识别是不是加密文件，
是的话会向你要口令。

| | |
| --- | --- |
| 密钥派生 | **PBKDF2-SHA256**，250000 次迭代，16 字节随机盐 |
| 加密 | **AES-GCM 256**，12 字节随机初始向量 |
| 文件格式 | `{ fmt, v, iter, alg, at, salt, iv, data }`（自描述，便于以后升级参数） |

导出文件长这样（元数据是**明文**的，只有 `data` 是密文）：

```json
{
  "fmt": "sitefilter-enc",
  "v": 1,
  "iter": 250000,
  "alg": "PBKDF2-SHA256/AES-GCM",
  "at": "2026-09-20T12:34:56.789Z",
  "salt": "…base64…",
  "iv": "…base64…",
  "data": "…base64 密文…"
}
```

几个必须说清楚的点：

- **每次导出的盐与初始向量都重新随机** —— 同样的密码、同样的数据，两次导出的密文完全不同。
- **AES-GCM 带完整性校验**：文件被改动过一个字节（哪怕改的是初始向量）都会**解密失败**，
  不会返回一段看起来像数据的垃圾。
- **扩展本身不保存密码**，口令只在内存里用于本次加解密。**忘记密码 = 文件打不开**，
  没有后门，也不在别处留副本。请自行记牢或另存。
- 明文导出仍然保留（点「导出 JSON 备份」会问你要不要加密；不加密就是可读 JSON，
  方便你手工改几条规则再导回）。

### 数据版本与迁移（第 1 项建议）
存储里带 **`schemaVersion`**，启动时自动 `migrate()`。导入旧备份会先升级到当前结构再写入。
以后我改数据结构时，你的老数据能被安全迁移，不再依赖零散的 `d.x || {}` 兜底。

> **三个文件的版本号必须一致**：`content.js` / `background.js` / `options.js` 各有一份 `migrate()`。
> 只改其中一两处的版本号，最轻是"迁移白跑一遍"，最重是 **content.js 用旧版本号写回 → 把数据降级**
> （新字段在下次读取时又被"补空"逻辑覆盖）。`_test_migrate.js` 里有断言守着这一条：
> 三处 `SCHEMA_VERSION` 必须相等、每处都要有对应的 `step N` 函数、各文件的读取函数都必须挂上新字段。
> v1.1.0 就是被这个守卫抓出了 `content.js` 忘了升级、以及 `background.js` 漏补 `expiredLog` 两个真实 bug。

### 规则整理与调试（v1.1.0 新增，见上文详述）

三件事一起用效果最好：

1. **规则体检**（规则管理页底部）—— 找出 0 命中的规则并**说明原因**，同时预警命中面过宽的屏蔽词。
2. **规则调试器**（卡片右键 →「调试这张卡」）—— 对某一张卡看**逐条规则的判定过程**，
   用的是页面里同一份逻辑，结论必然一致。
3. **候选规则**（发现 & 推荐页底部）—— 后台按「覆盖率 × 精确率」归纳出"你屏蔽的人还有什么共同点"，
   一键采纳或忽略。

### 性能：增量提取（第 3 项建议）
同一张卡片只跑一次内容提取（用 `WeakMap` 缓存 + 轻量签名校验）。
无限滚动 / 瀑布流页面每次追加新卡片时，**只计算新增的那批**，长列表 CPU 占用明显下降。
> 签名会**排除我们自己注入的按钮**（♥ / ⏳ / 仍然查看），否则每轮 pass 签名都会漂移、缓存永远命中不了。
> 卡片内容被就地更新（懒加载标题、换图）时签名变化，缓存自动失效重新提取。

## 九、常见问题

**Q：悬浮球没出现？**
A：确认当前网址在「监管站点」列表里且已启用；或者开启「下载链接探测 + 非监管站点也探测」。

**Q：片商 / 系列页是空的？**
A：该维度的自动识别依赖站点把链接写成 `/studio/`、`/series/`、`/director/` 这类路径。
列表页通常不展示这些信息（多在详情页）。如果某站用了别的路径，你可以在「完整设置」里
用**标题关键词 + 正则**规则手动覆盖，或告诉我路径我再补进识别表。

**Q：卡片没被屏蔽 / 屏蔽错东西了？**
A：打开面板 →「本页」，看识别到的各维度数量是否正确。
- 数量为 0 → 到「监管站点」给这个站点填**卡片选择器**（F12 看卡片的 class）。
- 数量对但屏蔽错 → 把规则的「作用范围」改成对应维度（仅女优 / 仅标签 / 仅片商…）。

**Q：磁力探测不到？**
A：确认该站的磁力不是由 JS 动态生成后注入的（本扩展在 DOM 变化后会重新扫描，一般能抓到）；
若站点把链接加密或放进 `canvas`/图片，则无法提取。

**Q：数据会同步到别的电脑吗？**
A：默认不会（纯本地方案）。两种跨设备方式：
1. **手动**：用「导出 JSON」在新机器上「导入」。
2. **自动**（可选）：在「通用设置 → 云同步」打开开关，数据走 **Chrome/Edge 账号同步通道**（不经任何服务器），换电脑自动带上。

### 打包上架（第 12 项建议）

```bash
python make_package.py                 # 普通打包 → dist/sitefilter-<版本>.zip
python make_package.py --ci            # 先跑语法检查 + 全部测试，过了才出包
python make_package.py --bump patch    # 版本号 1.0.0 → 1.0.1，写回 manifest 并记 CHANGELOG
python ci.py                           # 一键门禁（本地与 CI 同一套逻辑）
python ci.py --release minor           # 门禁通过 → 抬次版本 → 出发布包
```

产物：
- `dist/sitefilter-<版本>.zip` —— 直接拖进
  [Chrome 开发者控制台](https://chrome.google.com/webstore/devconsole) 或 Edge 的扩展商店提交；
- `dist/sitefilter-<版本>/` —— 解压版，`chrome://extensions` → 开发者模式 → **加载已解压的扩展程序**；
- `dist/build-info.json` —— 版本、`schemaVersion`、构建时间、git hash / 是否 dirty、
  每个文件的 sha256、以及**这次打包前跑测试的结果**。出问题时先看这个。

`schemaVersion: 6` · `manifest version: 1.2.0`

**打包脚本做了什么**：只收录**白名单文件**（而不是"排除"——避免漏排测试/临时文件）、校验
manifest 必填字段与图标真实尺寸、检查 `default_locale` 之类会导致「加载失败」的坑、
打完包再回头扫一遍 zip 里有没有混进测试文件。`--ci` 时任何测试失败会**直接中止且不产出 zip**，
避免"测试挂了但包已经发出去了"。

**CI**：`.github/workflows/ci.yml` 在每次 push / PR 跑 `python ci.py`（Node 20 与 22 双版本），
产物作为 artifact 上传；`.github/workflows/release.yml` 在打 `v*` tag 时**先校验 tag 与
manifest 版本一致**，再出包并附到 GitHub Release 上。版本号请在本地用
`python ci.py --release patch` 自增后再打 tag，避免两边对不上。
